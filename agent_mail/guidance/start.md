# Start with the shared work

Use Agent Mail when findings, questions or work need to remain available to
Eric and other tasks. Handle an ordinary bounded question directly in the
existing stream. Add a named stream or delegated lane when a distinct topic
or multiple contributors benefit from it. Plans, comments, orchestration and a
separate reviewer are optional; follow Eric's chosen amount of collaboration.

## Find the current context

Discover the connected server's tools and resource descriptions. Call
`project_context` to identify its project root and default stream; do not infer
these from your current directory. Use `list_streams` and `read_stream` to find
the outcome and relevant discussion. This server is bound to one existing
same-host database. An access or path failure needs resolution, not a private
replacement database.

Find the current direction, your role and actor label, owned item, write scope,
reviewer, checkpoint and next authorized action where applicable. A replacement
session retains its recorded role; copied context does not assign a new one.
If required assignment details are missing, ask in context before doing the
affected work. The server's tool schemas describe available operations and
arguments; discover them rather than guessing calls.

## Contribute at the right scale

Keep findings, sources, questions, assignments and decisions in the shared
feed. Reply to the discussion you address; correct mistakes with a new reply,
leaving the original available. A proposal remains distinct from Eric's decision.
A stream created for related work needs an announcement on the outcome stream
so other participants can find it.

The checklist contains actionable work within agreed scope, intended to be
finished. Future ideas stay in the feed for discussion until accepted as work.
Adding an item does not claim it or authorize unrelated implementation. A plan
is useful when proposed work needs discussion before becoming actionable; do
not turn every direct contribution into a plan or checklist exercise.

Read `agent-mail://guidance/roles` when coordinating, taking delegated work or
reviewing. Before a wait, continuation or closeout, read
`agent-mail://guidance/continuity`.

## What this local iteration provides

Streams expose the existing SQLite boards, append-only posts and shared
checklist through local stdio MCP. Actor labels are trusted attribution, not
authentication. Separate tasks keep their normal permissions; feed posts do
not approve crossing a permission boundary.

Plan editing, comments on plans, accepted-plan promotion and persistent
orchestrator claims are not implemented in this iteration. Record
relevant context in the feed without presenting that as those product features.
Guidance does not prove model compliance. The service supplies no hosted
transport, scheduler, automatic agent wake-up or runtime control. Actual host
connection and behavior need evidence at that boundary.
